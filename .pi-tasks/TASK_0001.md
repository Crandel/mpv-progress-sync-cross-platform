CONTEXT
- `main.lua` has two event handlers: `file-loaded` (restore) and `shutdown` (save), plus a periodic timer (1s) that updates the `position` global only when `isPlaying` is true.
- The `file-loaded` handler decodes JSON via `pcall(decode, content)`, validates `type(data) == "table" and data.loc ~= nil`, then seeks via `mp.commandv("seek", data.loc, "absolute+exact")`; it returns early on any error or missing `loc`.
- The `shutdown` handler builds a Lua table `{ loc = position }`, encodes it with `encode(data)`, and writes the JSON string to the position file; it only saves when `position > 2` and resets to 0 when `duration - position <= 5`.
- The `isPlaying` flag is set to `false` at shutdown start to prevent saving a nil `time-pos` (mpv clears it during exit).
- The decoder (`lib/decoder.lua`, vendored lunajson) already tolerates extra keys in JSON objects — it parses all key-value pairs into the returned table, so adding a `speed` key will not break decoding.
- The encoder (`lib/encoder.lua`, vendored lunajson) encodes any Lua table with string keys to JSON; adding `speed` as a number field is a simple table key addition.
- The filename hashing strategy uses MD5 of `file-size + duration` (or `force-media-title` for YouTube), stored in `currentFilename`, and sanitized with `string.gsub(currentFilename, "[^%w%.%-_]", "_")` before use as a filename.
- The position folder is resolved once at startup via `scriptDir .. '/positions/'` and used consistently in both `file-loaded` and `shutdown` handlers.
- mpv's `mp.get_property_number("speed")` returns the current playback speed as a number (e.g., 1.0 for normal, 0.5 for half speed, 2.0 for double), and `mp.commandv("set", "speed", <value>)` applies it.
- There is no existing mpv event callback for speed changes in the codebase; speed is only captured at shutdown currently.
- The shutdown handler re-sanitizes the filename and re-resolves `filepath` — it does not reuse the `filepath` set during `file-loaded`, so the speed-save code must follow the same pattern.
- The `file-loaded` handler returns early after seeking if `data.loc == nil`; speed restoration must happen before or alongside the `loc` seek, not after.

## spec

GOAL
  Extend `mpv-progress-sync/main.lua` to persist the current playback speed alongside the existing playback position (`loc`). On `file-loaded`, if the saved JSON contains a `speed` key, apply it via `mp.commandv("set", "speed", <value>)` after seeking to `loc`. On `shutdown`, capture the current speed via `mp.get_property_number("speed")` and include it in the saved JSON alongside `loc`.

CONSTRAINTS
  - Modify only `mpv-progress-sync/main.lua`; do not touch `lib/decoder.lua`, `lib/encoder.lua`, `lib/md5.lua`, `lib/sax.lua`, or any other library file.
  - Preserve the existing JSON schema: the `loc` key remains unchanged and functionally identical — its value, encoding, and semantics are exactly as they are today.
  - Add `speed` as a new top-level key in the same JSON object (e.g. `{ "loc": ..., "speed": ... }`); do not restructure or rename existing keys.
  - Backward compatibility: position files written by the current version (without a `speed` key) must load without error and must not alter playback speed — if `data.speed` is `nil`, skip the speed-setting call entirely.
  - In the `file-loaded` handler, restore speed only after the `data.loc` seek succeeds (i.e., after the `mp.commandv("seek", data.loc, "absolute+exact")` line), and only when `data.speed` is present and numeric.
  - In the `shutdown` handler, add `speed = mp.get_property_number("speed")` to the `data` table alongside `loc = position`; the existing conditional logic (`position > 2`, `finalPosition <= 5`) remains unchanged.
  - Do not alter the periodic timer logic (the 1-second `mp.add_periodic_timer` call and its callback), the filename hashing strategy, file paths, the `positions/` folder structure, or any existing error-handling patterns.
  - Do not introduce new dependencies or external services.
  - Preserve all existing `print()` and `mp.osd_message()` calls.

ACCEPTANCE
  1. A position JSON file written by the modified script contains both `loc` and `speed` keys (e.g. `{"loc":123.45,"speed":1.5}`).
  2. Opening a file whose position JSON includes a `speed` key causes mpv to seek to the saved position AND apply the saved speed via `mp.commandv("set", "speed", <value>)`.
  3. Opening a legacy position JSON (without a `speed` key) causes mpv to seek to the saved position but does not change the playback speed — the script must not call `mp.commandv("set", "speed", ...)` when `data.speed` is absent.
  4. The periodic timer callback (`mp.add_periodic_timer(1, ...)`) and its body are unchanged — it still reads `time-pos` and assigns to the global `position` variable.
  5. The filename hashing logic in `getFilename()` (MD5 of `file-size + duration` or `force-media-title`) is unchanged.
  6. All existing error-handling patterns (`io.open` failure checks, JSON parse error handling with `mp.osd_message`, type checks on `data`) are preserved verbatim.
  7. The script remains a single-file Lua script with no new dependencies.
